# Repository layout and ownership

## Status and allocation rule

This is the intended physical allocation supporting [ARCHITECTURE](ARCHITECTURE.md), [DECOMPOSITION](DECOMPOSITION.md), [SPEC](SPEC.md) and [PLAN](PLAN.md). At preparation, the root guidance, bundled plugin and development documents exist; application, tests, schema and build tooling below are proposed paths, not implemented artifacts.

Keep all project-owned production code in root `tetris.html`. Logical component boundaries use named inline sections, not runtime imports. Do not create a separate source tree that is bundled into a hidden second application implementation. The delivered HTML is the application source exercised by tests and copied into packages.

## Component-to-path map

| Physical owner | Contents / logical responsibility | Verification / consumers |
| --- | --- | --- |
| `tetris.html`: semantic markup and inline style | Five panels, controls, Canvas elements, focus/error/accessible text and responsive styling (C7) | Browser input, DOM, geometry and screenshot checks |
| `tetris.html`: `tetris-core` inline script | Pure C1-C6 rule/model services and definitions, with injected randomness/time/ID/UTC providers | Extracted-core Node harness called by pytest; real browser uses the same functions |
| `tetris.html`: embedded snapshot-schema JSON block | C5's authoritative Draft 2020-12 schema representation | Runtime structural/semantic validation; schema export/parity checks |
| `tetris.html`: inline application script | C7 rendering/input, C8 controller, C9 cookie/history integration and C11 file/worker lifecycle | Real HTML browser tests, adapter failure injection at defined seams |
| `tetris.html`: embedded SQLite worker source | C10 SQLite codec and worker-local validation bootstrap; only external import is the pinned sql.js JavaScript library | Bounded worker/browser tests and independent SQLite file inspection |
| `schemas/tetris-save.schema.json` | Inspectable schema companion exported from the embedded canonical schema; no independent schema edits | Parsed-content parity and jsonschema checks; release artifact copied as `tetris-save.schema.json` |
| `VERSION` | Current release version; checked against embedded HTML version and release metadata | Artifact/source/tag consistency checks |

The inline core may expose a frozen namespace of domain/model functions; the harness extracts its exact script text and executes it with bounded Node evaluation. The application controller owns all live state and browser effects. Test fixtures do not introduce alternate collision, scoring or schema implementations.

## Tests and development environment

| Path | Ownership |
| --- | --- |
| `tests/test_core.py` | Geometry, source/hold, scoring, timing, landing, bonus and game lifecycle contracts through the same extracted core |
| `tests/test_settings.py` | Typed settings, precedence, cookies/URL, live application and browser write/rollback cases |
| `tests/test_browser.py` | Actual HTML keyboard/buttons/focus/pause, Canvas/previews, panel geometry and screenshots in Chromium/Firefox |
| `tests/test_persistence.py` | Snapshot validation, JSON/SQLite round trips, malformed/schema/resource cases, download/restore and unchanged-state assertions |
| `tests/test_artifacts.py` | Single-file dependency boundary, schema/version/name/checksum/archive/installation checks |
| `tests/fixtures/` | Small explicit valid/invalid golden inputs; larger or corrupt databases generated by test helpers rather than committed opaque blobs |
| `tools/core_harness.mjs` | Bounded extraction/execution of the actual inline core; no npm dependency or duplicated game implementation |
| `requirements-dev.txt`, `pytest.ini` | Pinned development-only pytest, Python Playwright and JSON Schema dependencies; test collection/marker settings |
| `.dev/python/`, `.dev/browsers/`, `.dev/profiles/` | Ignored project/job-owned dependency target, compatible managed browser binaries and disposable state; no personal/global browser reuse |
| `.test-results/` | Ignored owned screenshots, downloaded snapshots and test evidence outputs |

Use pytest as the test runner. Python/Node and browser tooling are development prerequisites only. Setup/check commands must be established and actually exercised during implementation before README/AGENTS present them as validated commands. Keep package installs isolated and follow the actual host's shell policy; Windows execution uses CMD, not PowerShell. Preserve inherited proxy/trust and documented browser recovery rules.

## Packaging, releases and documentation

| Path | Ownership / artifact rule |
| --- | --- |
| `tools/export_schema.py` | Produce/check the schema companion from the canonical embedded JSON |
| `tools/package.py` | Validate version/single-file boundary and stable asset names, build the browser ZIP and checksums; exclude development/secret/cache content |
| `tools/verify_release.py` | Check pinned release-source/tag/version, hosted asset inventory and downloaded byte/checksum integrity |
| `.github/workflows/verify.yml` | Run applicable pinned development checks, including artifact-name/schema checks, without production runtime dependencies |
| `.github/workflows/release.yml` | Verify/package the pinned release source and support the authorized publishing path with explicit permissions and stable asset names |
| `dist/` | Ignored generated `tetris.html`, `tetris-browser.zip`, `SHA256SUMS.txt` and applicable `tetris-save.schema.json`; never treated as an alternate source tree |
| `RELEASE-NOTES.md` | Current complete release body, installation and evidence/limitations; Git and GitHub preserve earlier release messages |
| `README.md`, `docs/INSTALL.md` | Current delivered-capability overview, actual setup/check commands when verified, browser/static-hosting installation, format/dependency limitations |
| `docs/dev/` and `docs/dev/spec/` | Governing development documents, focused contracts and adjacent preparation QC reports |
| `docs/dev/reports/phases/<phase>/` | Milestone `<milestone>.md` and `PHASE-REPORT.md`, with actual checks/findings/TODOs and assigned boundary links |
| `docs/dev/reports/IMPLEMENTATION-REPORT.md` | Final delivered scope, complete evidence limits and aggregated remaining TODOs |

The browser ZIP contains only the application HTML, applicable schema, license and installation instructions. Downloaded/generated evidence remains outside tracked source unless a concise owning report explicitly references a retained artifact. Never package credentials, `.dev`, tests, source tools, the bundled plugin or manual conversation records.

Root `AGENTS.md` owns current navigation and verified command guidance. Preserve the bundled plugin and standalone writing skill; neither is an application dependency or a target for routine implementation edits. `docs/ai-logs/` remains manual historical provenance under its scoped instructions. Credentials remain only in ignored, untracked `gh.tkn`; root `*.tkn` exclusion must survive changes.

All component, contract, test, package and report responsibilities have a physical owner. No placement decision remains unresolved for TASKS derivation.
